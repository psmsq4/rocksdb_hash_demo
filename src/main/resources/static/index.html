벤치마크 HEAD, UPSTREAM, SKIPLIST를 같은 작업으로 동시에 측정 아키텍처 UPSTREAM과 HEAD의 HashSkipList 구조 비교

HASH(Rocksdb)

[돌디비] 단국대학교 소프트웨어학과 21학번 신승호

각 카드는 같은 작업을 HEAD UPSTREAM SKIPLIST memtable로 동시에 실행하고, 1초마다 지표를 수집해 비교합니다.

측정 설정

100,000개 단위
128MB 단위 (최소 64MB, RocksDB 기본값)
key 형식 prefix는 첫 | 까지
bucket 높이 HEAD, UPSTREAM의 bucket마다 있는 skiplist의 최대 높이
preload KV를 먼저 메모리에 모두 만들고 쓰기만 잽니다
WAL write-ahead log 기록
정확도 검증 끝나면 전량 flush 전후로 전체를 key 순서대로 읽어 내용 해시를 비교
동시 memtable 쓰기 HEAD, SKIPLIST만 해당. UPSTREAM은 지원하지 않아 항상 끔
Put을 하는 쓰기 스레드. 프로세스마다 CPU 4개라 4 이하를 권합니다
prefix scan과 total-order scan을 각각 이만큼
scan 한 번에 읽는 entry 수, 10개 단위
hit, miss, 없는 종목 조회를 각각 이만큼
